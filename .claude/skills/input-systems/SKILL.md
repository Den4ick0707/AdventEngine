# Ввід

Ввід — частина модуля `platform` (тема «Платформа» в `docs/architecture.md`). GLFW видно лише в `platform/src`.

## Архітектура
- Гра читає іменовані дії (`jump`, `move`), а не клавіші. Прив'язка клавіш до дій — дані (файл налаштувань).
- Стан оновлюється раз на кадр після `poll_events`: callback-и GLFW лише записують події, а модуль вводу
  перетворює їх на стан кадру.
- Два типи читання: подія кадру (`pressed`, `released`) для одноразових дій і утримання (`held`, значення осі)
  для безперервних. Плутанина дає подвійні спрацювання або пропуски.
- Клавіатура прив'язується за фізичним кодом (scancode, у GLFW `key` відповідає позиції на US-розкладці),
  щоб WASD залишалися на місці на інших розкладках. Назву клавіші для інтерфейсу — `glfwGetKeyName`.

## Аналогові стіки
- Радіальна мертва зона за довжиною вектора, не окремо по осях:
  ```cpp
  const float len = glm::length(stick);
  if (len < dead) return glm::vec2(0.0F);
  const float scaled = std::min((len - dead) / (1.0F - dead), 1.0F);
  return stick / len * std::pow(scaled, curve);
  ```
- Крива відгуку і чутливість налаштовуються окремо.
- Геймпад: `glfwGetGamepadState` з мапінгом SDL.

## Фіксований крок
Подія натискання між двома кроками симуляції не повинна загубитися: дія, натиснута в кадрі, утримується
до найближчого `on_fixed_update`. Буферизація (близько 0,1 с) прощає трохи завчасне натискання.

## Перепризначення
- Захоплення наступного вводу, перевірка конфлікту з іншими діями, збереження у файл, скидання до стандартних.
- Не можна відв'язати клавішу, без якої не дістатися меню.

## Доступність
Повне перепризначення, перемикання замість утримання, налаштування чутливості, жодних обов'язкових
одночасних натискань.
