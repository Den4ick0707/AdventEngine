## Пріоритет при конфліктах
Приклади в скілах групи awesome-gamedev написані на GDScript / C# (Godot, Unity), а `shader-programming` показує GLSL у стилі OpenGL (`#version 330`, uniform-змінні без дескрипторів).
Тому в `CLAUDE.md` додано правило: **скіли проєкту мають пріоритет**, а сторонні — це концепції, які треба переносити на C++20 / Vulkan за правилами проєкту.
Так само `cpp-pro` згадує FetchContent і Conan, але в проєкті залежності — лише через git submodules.

## Звіт перевірки безпеки

### Як перевіряли
- Кожен репозиторій завантажено в окрему ізольовану папку; **жоден файл із них не запускався**.
- Автоматичне сканування всіх файлів: приховані Unicode-символи (zero-width, bidi), фрази prompt injection, `curl | bash`, base64-декодування, `eval`/`exec`, доступ до ключів і `.env`, мережеві виклики, руйнівні команди, обхід дозволів, символьні посилання, бінарні та виконувані файли.
- Ручне прочитання кожного відібраного `SKILL.md` і пошук команд, URL та звертань до агента в довідкових файлах.

### Результат для відібраних скілів: чисто ✅
- Лише Markdown-файли: жодних скриптів, хуків, виконуваних файлів чи символьних посилань.
- Жодних прихованих символів, прихованих інструкцій чи спроб змінити поведінку Claude.
- Немає поля `allowed-tools` у frontmatter — скіли не надають собі дозволів на інструменти.
- Знайдені збіги — лише навчальні приклади коду (наприклад, `FetchContent` з URL репозиторію fmt у `cpp-pro`).
