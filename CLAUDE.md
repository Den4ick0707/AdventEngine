# AdventEngine

Модульний 3D-рушій на C++20 і Vulkan 1.3: легке ядро, модулі (рендерер, сцена, ассети, анімація, у майбутньому
трасування променів), застосунки поверх (редактор, sandbox, ігри). Проєкт довгостроковий: рішення приймаються
з розрахунку на розвиток, а не на одну демонстрацію.

## Спілкування і тексти
- Відповідай українською, у форматі діалогу: коротко, по суті, з уточнювальними питаннями, а не довідником.
- Документація: без емодзі, рівний технічний стиль, таблиці й списки замість довгих абзаців.
- Ідентифікатори, коментарі в коді, повідомлення комітів і назви файлів ADR — англійською.

## Як працювати
- Поточний етап і план — `docs/roadmap.md`. Відкриті архітектурні питання — `docs/architecture.md`, розділ
  «Відкриті питання». Якщо задача зачіпає відкрите питання, спитай, а не обирай мовчки.
- Перш ніж писати нову підсистему, запропонуй дизайн і дочекайся згоди. Рішення, що впливають на архітектуру,
  фіксуй через `/adr`, потім онови `docs/architecture.md`.
- Рухайся малими кроками: кожен збирається, проходить `./dev ci` і запускається.
- Зміни йдуть через гілку і Pull Request у `dev` (`CONTRIBUTING.md`). Перед комітом — `./dev ci`.
- Документацію змінюй там, де тема описана (таблиця нижче), а не дублюй її в іншому файлі.

## Скіли
Скіли в `.claude/skills/` — короткі робочі правила для конкретних задач:

| Скіл | Коли |
|------|------|
| `build-test` | збирання, тести, CI, `./dev`, бібліотеки у `vendor/` |
| `engine-module` | новий модуль рушія |
| `vulkan-renderer` | будь-який Vulkan-код |
| `shader-pipeline` | шейдери, дескриптори, пайплайни |
| `skeletal-animation` | glTF, скелет, анімація, скінінг |
| `adr` | фіксація архітектурного рішення |
| `cpp-pro` | сучасний C++, пам'ять, конкурентність |
| `performance-optimization` | профілювання і продуктивність |
| `physics-tuning` | фіксований крок, інтерполяція, стабільність фізики |
| `camera-systems` | камери від першої і третьої особи |
| `input-systems` | дії, прив'язка клавіш, геймпад |
| `shader-programming` | простори координат, UV, ефекти в шейдерах |

Пріоритет при конфлікті: цей файл, потім документи з `docs/`, потім скіли.

## Чого не робити
- Не додавай залежності без запиту. Нова бібліотека — тека у `vendor/`, ціль у `vendor/CMakeLists.txt`,
  рядок у `vendor/README.md` і ADR.
- Не вимикай validation layers у Debug, щоб прибрати помилки, — виправляй причину.
- Не змінюй структуру модулів і правила залежностей без ADR.
- Не копіюй сторонній код поза `vendor/`. Правки у `vendor/` — окремими комітами з позначкою `// ADVENT PATCH:`.
- Не форматуй і не лінтуй `vendor/`.
