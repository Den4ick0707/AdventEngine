# 0001. Git submodules for dependencies

- Статус: Superseded by [0005](0005-vendored-dependencies.md)
- Дата: 2026-11-02

## Контекст
Попередня версія репозиторію зберігала копії бібліотек (glfw, glm, imgui, json, stb) прямо в `external_libs/`: 2 542 файли і понад 668 тис. рядків. Такі копії роздувають історію Git, їх неможливо оновити однією командою, і не видно, яка саме версія використовується.

## Розглянуті варіанти
1. **Копії в репозиторії (vendoring).**
   - Плюси: працює без мережі.
   - Мінуси: велика історія, ручне оновлення, невідома версія.
2. **Git submodules.**
   - Плюси: точна версія (коміт або тег) зафіксована в репозиторії; бібліотеки не потрапляють в історію; оновлення однією командою.
   - Мінуси: треба клонувати з `--recursive`.
3. **Менеджер пакетів (vcpkg / Conan).**
   - Плюси: бінарні кеші, транзитивні залежності.
   - Мінуси: додатковий інструмент для встановлення й налаштування; складніше для навчального проєкту.
4. **CMake FetchContent.**
   - Плюси: нічого не треба клонувати вручну.
   - Мінуси: завантаження під час конфігурації, без мережі не збирається; версії розкидані по CMake-файлах.

## Рішення
Git submodules у `third_party/`, кожен зафіксований на тезі релізу (для stb, що не має тегів, — на коміті). У `.gitmodules` стоїть `shallow = true`, щоб не завантажувати повну історію бібліотек. Цілі CMake для всіх бібліотек описані в одному місці — `third_party/CMakeLists.txt` — і додаються як `SYSTEM`, щоб їхні попередження не змішувалися з нашими.

## Наслідки
- Клонування: `git clone`, потім `git submodule update --init --recursive --depth 1`. Прапорець `--depth 1` обов'язковий: теги зафіксовані не на вершині гілок, тож без нього Git завантажує повну історію бібліотек (~370 МБ замість ~35 МБ). Кореневий `CMakeLists.txt` перевіряє, що submodules на місці, і підказує команду.
- CI використовує `actions/checkout` з `submodules: recursive`.
- Оновлення бібліотеки — окремий коміт зі зміною тегу (див. скіл `/build-test`).
