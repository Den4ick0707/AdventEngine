# 0004. Main loop with a fixed simulation timestep

- Статус: Accepted
- Дата: 2026-11-02

## Контекст
У попередній версії `Application::Run` передавав в `Update` значення `deltaTime = 0` (із позначкою TODO). Рушію потрібен реальний час кадру для анімацій і камери, а також стабільна симуляція, яка не залежить від FPS: фізика й геймплей поводяться по-різному на 30 і 144 FPS, якщо інтегрувати зі змінним кроком.

## Розглянуті варіанти
1. **Лише змінний крок:** `update(dt)`. Просто, але симуляція залежить від FPS.
2. **Лише фіксований крок.** Стабільно, але анімація і камера смикаються, коли частота кадрів не кратна кроку.
3. **Гібрид:** фіксований крок для симуляції, змінний — для решти, інтерполяція в рендері.

## Рішення
Гібрид (варіант 3) у `runtime::Application`:
- `on_fixed_update(step)` — 60 Гц за замовчуванням (`ApplicationConfig::fixed_timestep_seconds`): фізика, геймплей;
- `on_update(dt)` — раз на кадр: анімації, камера, UI;
- `on_render(alpha)` — `alpha` ∈ [0, 1) для інтерполяції між станами симуляції.

Допоміжні класи в `core`:
- `FrameClock` обмежує delta до 0,25 с, щоб брейкпоінт не дав гігантського кроку;
- `FixedTimestep` виконує не більше 8 кроків за кадр, решту часу відкидає.

Поки вікно згорнуте, цикл чекає подій (`wait_events`) і не навантажує процесор.

## Наслідки
- Обидва класи покриті модульними тестами (`tests/core/`).
- Поки немає swapchain з vsync, кількість кадрів обмежує `ApplicationConfig::max_fps` (sandbox — 240). Після появи FIFO-презентації це обмеження в sandbox можна прибрати.
