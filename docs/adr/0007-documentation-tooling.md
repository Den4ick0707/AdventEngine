# 0007. Documentation tooling: Doxygen site

- Статус: Accepted
- Дата: 2026-11-05

## Контекст
Проєкт має ручну документацію в Markdown (`docs/`, `README.md`, ADR) і код, який треба пояснювати класами
та їхніми зв'язками. Потрібен один сайт, де є і ручні розділи, і довідник класів з діаграмами, і який можна
відкрити за посиланням. Документація має збиратися офлайн, як і код (ADR 0005).

## Розглянуті варіанти
1. **Doxygen + Graphviz + doxygen-awesome-css.**
   - Плюси: читає C++ напряму; будує список класів і діаграми; включає Markdown як сторінки;
     один інструмент без Python-залежностей; тема робить вигляд сучасним.
   - Мінуси: застарілий вигляд без теми; обмежена підтримка частини Markdown.
2. **Doxygen + Sphinx + Breathe.**
   - Плюси: гнучкіша ручна документація.
   - Мінуси: два інструменти й Python-середовище; складніше підтримувати.
3. **Лише Markdown на GitHub.**
   - Плюси: нічого не треба збирати.
   - Мінуси: немає довідника класів і діаграм.

## Рішення
Варіант 1.
- Конфігурація — `docs/Doxyfile`; збирання — `./dev docs`, результат у `build/docs/html`.
- Вхід: Markdown-документи і публічні заголовки `engine/*/include`. Коментарі `///` — довідник класів.
- Діаграми колаборації та ієрархії через Graphviz, лише для класів рушія; приватні поля показуються,
  бо саме вони описують володіння.
- Markdown-файли пишуться для GitHub; фільтр `docs/tools/doxygen_md_filter.py` під час збирання робить
  кореневий README головною сторінкою і перетворює відносні посилання на посилання сайту.
- Тема `doxygen-awesome-css` v2.5.0 — копія у `vendor/` (ADR 0005), замість submodule.
- CI перевіряє збирання без попереджень (`./dev docs --strict`); `docs.yml` публікує сайт на GitHub Pages
  після кожної зміни в `dev`.
- Мова інтерфейсу сайту — англійська: український переклад Doxygen застарів (з версії 1.8.4).
  Вміст сторінок і коментарів — як написано.

## Наслідки
- Для `./dev docs` потрібні `doxygen`, `graphviz` і `python3`; `./dev setup --install` ставить перші два.
- Публічний API документується коментарями `///` (`docs/coding-style.md`).
- Нові Markdown-документи додаються в `INPUT` у `docs/Doxyfile`, інакше їх не буде на сайті.
