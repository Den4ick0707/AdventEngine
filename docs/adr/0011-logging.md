# 0011. Logging: categories, sinks, no allocations

- Статус: Accepted
- Дата: 2026-11-05

## Контекст
Поточний лог має рівні, один sink і форматування через `std::format`, яке виділяє пам'ять у купі на кожне
повідомлення. У модульному рушії потрібно бачити, який модуль пише, фільтрувати по модулях, зберігати лог
у файл і показувати його в редакторі, не гальмуючи кадр.

## Рішення
- **Категорії.** Кожен модуль пише від свого імені: `log::info(k_log, "...")`, де
  `inline constexpr log::Category k_log{"renderer"}`. У виводі — `[renderer]`. Рівень задається для категорії
  окремо: `--log renderer=trace,assets=warn`.
- **Sinks.** Кілька одночасно: консоль (кольори за рівнем), файл, пізніше — панель редактора.
- **Файл завжди.** `logs/advent-<дата-час>.log`, зберігаються останні 10 запусків. Лог є одразу, коли щось
  пішло не так у користувача.
- **Без виділень.** Форматування в буфер на стеку (`std::format_to_n`, 1 КБ); довші повідомлення обрізаються
  з позначкою `…`.
- **Release.** `trace` і `debug` вирізаються під час компіляції (`if constexpr`); аргументи не обчислюються.
- **Асинхронний запис** у файл — разом із темою «Потоки».

## Наслідки
- API логу змінюється: перший аргумент — категорія. Наявні виклики переписуються.
- Smoke-тест і далі шукає `[error]` у виводі консолі. Повідомлення Vulkan зберігають позначку
  `[vulkan:<джерело>]`, на яку орієнтується `./dev smoke`.
