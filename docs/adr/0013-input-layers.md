# 0013. Input: raw device state in platform, actions in a module

- Статус: Accepted
- Дата: 2026-11-05

## Контекст
Грі потрібні дії з перепризначенням клавіш і підтримкою геймпада; редактору — гарячі клавіші, миша у вікні
перегляду і введення тексту. Симуляція працює з фіксованим кроком, тож натискання між кроками не можна губити.

## Розглянуті варіанти
1. **Усе в platform.** Один модуль, але кожен застосунок отримує систему дій, навіть якщо вона йому не потрібна.
2. **Сирий ввід у platform, дії окремим модулем `input`.** Чітка межа; дії можна замінити або не підключати.

## Рішення
Варіант 2.

- **Сирий ввід (platform)** — стан пристроїв на кадр без інтерпретації:
  клавіатура за фізичним положенням клавіші (pressed / held / released), миша (позиція, зміщення, кнопки,
  колесо; raw motion для камери), геймпади (значення як є, без мертвої зони), текстовий ввід (символи з
  урахуванням розкладки). Callback-и GLFW лише записують події; стан кадру формується після `poll_events`.
- **Модуль `input`** — дії поверх сирого вводу: `actions.pressed("jump"_sid)`, `actions.axis("move"_sid)`;
  прив'язки в `project://input.json`, перепризначення користувача в `user://settings.json`; радіальна мертва
  зона стіків; натискання утримується до найближчого кроку `on_fixed_update`; буферизація натискань.
- **Кілька вікон.** API платформи не припускає єдиного вікна; підтримка кількох вікон вирішується в темі «Редактор».

## Наслідки
- `platform` отримує тип стану вводу; `input` — новий модуль у шарі модулів, залежить від `platform` і `core`.
- Редактор використовує сирий ввід, гра — дії.
