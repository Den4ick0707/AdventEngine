# 0022. Serialization: field reflection, JSON scenes, component versions

- Статус: Accepted
- Дата: 2026-11-05

## Контекст
Сцени (ADR 0018) зберігаються у файли й мають відкриватися через роки після змін у компонентах.
Компоненти додають різні модулі, зокрема сторонні. Редактору потрібні інспектор полів і копія світу для Play.
Посилання у файлах — лише через `Uuid` (ADR 0009).

## Розглянуті варіанти
- **`serialize`/`deserialize` вручну в кожному компоненті.** Просто, але багато однакового коду, легко забути поле;
  інспектор і копіювання світу все одно потребують окремого опису.
- **Рефлексія полів.** Один опис компонента дає збереження, завантаження, інспектор і копіювання.
- Формат: **JSON** (nlohmann/json уже у `vendor/`, зручно для git) або **бінарний** (швидше, але нечитабельний
  і без зручних злиттів).

## Рішення
**Рефлексія.** Модуль при реєстрації компонента описує його поля:

```cpp
reflect<Light>("light", 2)
    .field("color", &Light::color)
    .field("radius", &Light::radius)
    .migrate(1, &migrate_light_v1);
```

- Опис типів і полів — у `core`, без залежностей. JSON-серіалізація світу — у модулі `scene` (nlohmann приватно).
- Підтримувані типи полів: числа, `bool`, enum (за іменем), рядки, вектори й кватерніони GLM, `Uuid`, масиви
  фіксованого розміру, вкладені описані структури. `AssetHandle<T>` пишеться як `Uuid` ассета,
  `Handle<Entity>` — як `Uuid` сутності.
- Поле, що існує лише під час роботи, позначається `.transient()` і не зберігається; обчислювані компоненти
  (`WorldTransform`, `JointMatrices`) не зберігаються цілком.
- Той самий опис використовують інспектор редактора і копіювання світу для Play.

**Формат сцени** — JSON:

```json
{
  "format": 1,
  "uuid": "…",
  "entities": [
    {
      "uuid": "…",
      "components": {
        "transform": { "version": 1, "position": [0, 1, 0], "rotation": [0, 0, 0, 1], "scale": [1, 1, 1] },
        "hierarchy": { "version": 1, "parent": "…" },
        "mesh":      { "version": 1, "asset": "…" }
      }
    }
  ]
}
```

**Зміни з часом:**
- Кожен компонент має версію. Старша версія у файлі проходить ланцюжок міграцій `1 -> 2 -> …`, які пише автор
  модуля. Поле, якого немає у файлі, отримує значення за замовчуванням без міграції; поле, якого немає в описі, —
  `[warn]` і пропускається.
- Компонент невідомого або вимкненого модуля зберігається як сирий JSON і записується назад без змін.
- `format` у заголовку — версія структури самого файлу; зміна структури — разом із міграцією файлу.
- Помилки завантаження — `Result` (ADR 0010); пошкоджена сутність пропускається з `[error]`, решта сцени завантажується.

## Наслідки
- Кожен компонент, що має зберігатися, описується через `reflect`; нереєстрований компонент не потрапляє у файл.
- Ключі компонентів (`"light"`) — стабільні імена; перейменування — лише з міграцією.
- Файл проєкту `.advent` (ADR 0012) і `.meta` (ADR 0019) використовують ту саму JSON-бібліотеку, але мають
  власні прості схеми без рефлексії.
- Бінарний формат для швидкого завантаження — пізніше, разом із власним форматом ассетів.
- Префаби — тема «Редактор»; вони використовують той самий формат.
