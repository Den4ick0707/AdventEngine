# 0025. Physics: Jolt behind an adapter module, interpolated rendering

- Статус: Accepted
- Дата: 2026-11-05

## Контекст
Іграм потрібні тверді тіла, колізії й запити (raycast). Найближча мета — диплом з трасування променів,
до якого фізика не входить, але рішення впливає на сцену: фізика оновлюється у `fixed_update` (60 Гц), а кадр
може виводитися частіше, тож без інтерполяції рух смикається.

## Розглянуті варіанти
- **Jolt Physics.** Сучасна, швидка, багатопотокова, чистий C++17, MIT.
- **PhysX 5.** Потужна, BSD-3, але велика і зі складним збиранням.
- **Bullet.** Перевірена, але застаріла й повільно розвивається.
- **Власна.** Корисно для навчання, але роки роботи до порівнянного рівня.

## Рішення
- Модуль `physics` — адаптер над Jolt. Публічний API рушія: компоненти (`RigidBody`, `Collider`,
  шари колізій), запити (`raycast`, `overlap`), події контактів (ADR 0015). Типи Jolt видно лише
  в `physics/src`; заміна бібліотеки не зачіпає інші модулі.
- Модуль необов'язковий: гра без фізики його не підключає. Jolt додається у `vendor/` з першою задачею з фізики,
  після трасування променів.
- Синхронізація зі сценою у `fixed_update`: `LocalTransform` кінематичних тіл -> Jolt, крок симуляції,
  Jolt -> `LocalTransform` динамічних тіл.
- Інтерполяція: перед кожним кроком `fixed_update` поточний `LocalTransform` копіюється в `PreviousTransform`
  тих сутностей, що його мають; рендерер інтерполює між ними за `alpha` (ADR 0004). Сутності без
  `PreviousTransform` за інтерполяцію не платять.

## Наслідки
- `PreviousTransform` — компонент модуля `scene`, доступний не лише фізиці, а будь-якому руху у `fixed_update`.
- Багатопотоковість Jolt узгоджується з системою задач рушія, коли вона з'явиться (ADR 0014).
