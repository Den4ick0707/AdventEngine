# 0026. Distribution: versions, game packaging, module tooling, releases

- Статус: Accepted
- Дата: 2026-11-05

## Контекст
Після диплома планується публічний реліз і розвиток за відгуками. Потрібно знати, як версіонується рушій
і його API, як гра пакується для гравця, як автори поширюють модулі (лише вихідним кодом, ADR 0006, 0017)
і що містить реліз рушія.

## Рішення

| Питання | Рішення |
|---------|---------|
| Версія рушія | одна версія SemVer для рушія і його API; до `1.0.0` мінорна версія може ламати сумісність. Модулі вказують сумісний діапазон в `engine_api` (ADR 0017) |
| Пакування гри | `./dev package <project>`: Release-збірка в теку з виконуваним файлом, SPIR-V шейдерами, ресурсами `engine://` і `project://assets/` разом із `.meta`. Без архіву, поки гра імпортує джерела (ADR 0019); пакувальний архів з'являється разом із власним форматом ассетів |
| Платформи | Linux і Windows, обидві в CI |
| Інструмент для модулів | `./dev module new <name>` — заготовка (`module.json`, CMake, `include/`, `src/`, тести); `./dev module pack <name>` — архів вихідного коду для поширення. Каталог модулів — пізніше |
| Релізи рушія | GitHub Releases (`release.yml`): вихідний код, готові sandbox і, пізніше, редактор для Linux і Windows |

## Наслідки
- Модулі `kind: editor` і бібліотеки лише для розробки (Dear ImGui) не потрапляють у пакет гри.
- `./dev package` і `./dev module` з'являються, коли їх потребуватиме перша задача; до диплома — не раніше
  за етап, на якому з'явиться модульна збірка (етап 4 плану).
- Підпис виконуваних файлів, інсталятори і автооновлення — поза рамками, до окремого рішення.
